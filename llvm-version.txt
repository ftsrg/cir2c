# The llvm-project revision cir2c builds against. This is the single source of
# truth: docker/build-llvm.sh clones it, the toolchain image bakes it in and
# publishes itself under this revision as its tag, CI and Release pull that
# exact tag, and the weekly check compares it against upstream.
#
# The value is one immutable revision — a release tag, or a full 40-character
# commit SHA. cir2c NEVER tracks a moving branch: a floating `main` would change
# the toolchain under an unchanged commit of this repository, so a green build
# would say nothing.
#
# A RELEASE TAG IS PREFERRED, but is not always possible. ClangIR is young and
# moves inside the LLVM development cycle, so the CIR a release emits can lack
# operations cir2c needs. This pin is such a case: it is llvm-project main
# during the LLVM 24 cycle, because no LLVM 24 release exists yet (upstream has
# only llvmorg-24-init, the branch point) and LLVM 23.1.0 has neither
# cir.fmuladd nor the current func_info attribute. The weekly check watches for
# the first release that can replace it.
#
# Read the "LLVM toolchain" section of README.md before changing this. Moving
# the pin means rebuilding the toolchain image and re-running the corpus suites.
#
# Comments and blank lines are ignored; the first remaining line is the ref.
